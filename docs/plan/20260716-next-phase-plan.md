## 0. 当前缺口（从 C1–C3 实测读出）

| 缺口 | 现象 | 含义 |
|------|------|------|
| C1 吞吐 vs 历史 | 现栈 b1 ~167 img/s vs 历史 ~1069 | 栈/对齐/配置未吃满，不是驱动回退 |
| C2 I/O 无差 | 256² 下 pinned ≈ pageable ~100 img/s | 算力主导；需更大图/批才能秀 S4 |
| C3 叙事 | dual 已快于 solo，但是 FC micro-app | 可升级为「更像业务」的两 stage |
| 质量指标 | C2 无 PSNR/观感 | 只有吞吐，缺「能不能用」 |
| 自动化 | cases 未进 CI 门禁 | 易漂移 |

## 2. Phase N1 — 深耕 C1/C2/C3（P0，建议先做）

### N1.1 C1 ResNet 拉近「真实可用」

| 任务 | 内容 | 成功标准 |
|------|------|----------|
| 对齐警告 | 查 `BufferMgr align 64`；输入 buffer 64B 对齐 / paddle SetXpuConfig | 警告消失或可解释 |
| 环境钉死 | 固定镜像 + wheel 版本写进 `run_c1` / Dockerfile 片段 | 他人一键复现 |
| 对比表 | 同机：旧数字说明 + 现栈 b1/b8/b32 | `c1` 报告更新一版 |
| 可选 FP16 | 若 paddle-xpu 支持 AMP/FP16 推理则加一列 | 有 FP16 行则更好 |

**工期**: 2–3 天 · **风险**: 低–中（框架侧）

### N1.2 C2 降噪「更大、更真」

| 任务 | 内容 | 成功标准 |
|------|------|----------|
| 分辨率矩阵 | 512² / 1024²（显存允许时）bench | 大图下 pinned vs pageable 出现可测差或说明算力仍主导 |
| 质量 | 干净图 + 加噪 + PSNR（或至少前后可视化说明） | 报告含质量小节 |
| 权重 | 标明 synth 仅吞吐；若有真权重则替换 | 文档诚实 |
| 批处理 | 多图目录 mode：张/s 汇总 | 更接近离线产线 |

**工期**: 2 天 · **风险**: 低

### N1.3 C3 流水线加厚一点

| 任务 | 内容 | 成功标准 |
|------|------|----------|
| 双缓冲 | 用户态双激活缓冲，尝试重叠 P2P 与对端 compute | 有 before/after 表 |
| 负载扫 | layers / feat 扫：何时 dual 赢、何时 P2P 税更大 | 决策曲线一页 |
| 同卡绑核 | 明确 xpu0↔1 与 xpu2↔3 各测一组 | 两卡对称验证 |

**工期**: 1–2 天 · **风险**: 低

### N1.4 工程

- `make cases` 增加「快速模式」（小分辨率/少 iter）与「完整模式」  
- 案例结果失败时非零退出（可选 `CASE_STRICT=1`）  
- 驱动 `make regression` 仍为硬门禁；cases 为软/可开关

## 5. Phase N4 — 仅按需（默认不做）

| 选项 | 触发条件 | 备注 |
|------|----------|------|
| 驱动再改 | 明确业务卡在 pageable/P2P 且 host_alloc 用不了 | S9 已证 pageable D2H 难抠 |
| SSE 跨 PD spike（原 S10） | 同卡 P2P 11 GB/s 仍不够 **且** 愿承担 hang 风险 | 默认关、独立分支 |
| 固件/SDK 升级 | 官方提供 INT8 或新 runtime | 非本仓可控 |
| 换代硬件 | 需要 LLM / INT8 / 大显存 | 评估 XPU2/3，非优化本驱动 |
