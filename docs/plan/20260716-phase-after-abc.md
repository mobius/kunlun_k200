## 2. 下阶段三条主航道（任选或组合）

### 航道 P — **产品化收口**（推荐默认，1 周）

把「能跑」变成「别人能稳定复现、能交给业务」。

| ID | 任务 | 成功标准 | 工期 |
|----|------|----------|------|
| P1 | **环境钉死** | 一份 `docs/impl/ENV.md`：驱动装载、参数、paddle 镜像/wheel、依赖 | 0.5d |
| P2 | **cases 质量门** | `CASE_STRICT=1 make cases`：关键数字缺失或崩溃 → 非零退出 | 1d |
| P3 | **C2 full 默认真跑** | full 模式含 512²（+可选 1024²）结果写入 SUMMARY | 0.5d |
| P4 | **C1 对齐复测** | 用 64B align 脚本在容器重跑，更新 c1 报告与历史对比说明 | 1d |
| P5 | **版本标签** | git tag `v1.0-k200-cases` + 结案说明一段 | 0.5d |

**产出**: 可对外说「v1.0：驱动+案例+演示包」。

---

### 航道 Q — **接真业务**（有真实模型/数据时，1–2 周）

用现有骨架换 **真实权重与 SLA**，而不是再发明 microbench。

| ID | 任务 | 触发条件 | 成功标准 |
|----|------|----------|----------|
| Q1 | **真降噪/超分模型** 替换 synth 权重 | 有 `.bin`/可导出权重 | 吞吐 + 可接受 PSNR/观感 |
| Q2 | **真小塔/排序模型** 替换 C4 FC 代理 | 有 FC/MLP 结构与权重 | 对齐线上 batch 的 samples/s |
| Q3 | **同卡双 PD 真实两 stage** | 业务可拆 stage | P2P 流水线 e2e 延迟/吞吐达标 |
| Q4 | **双卡弱耦合上线形态** | 需要 2 卡总吞吐 | 沿用 C5 进程模型，测产线 QPS |

**原则**: 业务给数据与成功指标；本仓提供路径（host_alloc / FP16 / P2P / 双卡）。

---

### 航道 R — **栈与数字拉齐**（可选，3–5 天）

专治「C1 离历史峰值很远」。

| ID | 任务 | 说明 |
|----|------|------|
| R1 | 固定历史同款容器/SDK 复现 1069 | 分清「栈差」还是「回归」 |
| R2 | paddle SetXpuConfig / 去 MKLDNN 干扰 / 减少 copy_from_cpu | 抬现栈 img/s |
| R3 | 输入预置 device、异步 stream（若 API 支持） | 减少 H2D 占比 |

**不做**: 为抬 C1 再改 KL1 DMA 核心路径（收益与风险不匹配）。

---

### 航道 S — **冻结 / 维护**（无新需求时）

| ID | 任务 |
|----|------|
| S1 | 仅修 bug、文档、依赖腐烂 |
| S2 | `make regression` + `CASE_MODE=quick make demo` 作为健康检查 |
| S3 | 新需求走「案例模板」：问题 → 指标 → 脚本 → `results/cases/` |

---

### 航道 X — **高风险 / 换代**（默认关闭）

| ID | 触发 | 说明 |
|----|------|------|
| X1 | 同卡 11 GB/s 不够 | SSE 跨 PD spike（原 S10），独立分支、默认关 |
| X2 | 官方 INT8/新 runtime | 跟 SDK，不自造 |
| X3 | LLM / 大显存 | 评估 XPU2/3，非本驱动优化 |
