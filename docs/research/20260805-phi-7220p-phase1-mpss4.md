# Phase 1 调研：7220P (KNL PCIe) 与 MPSS 4

**日期**: 2026-08-05  
**卡**: Intel Xeon Phi **7220P**（Knights Landing x200 **PCIe 协处理器**）  
**本机 PCI ID**: **`8086:2260`** + **`8086:2264`**，subsys `8086:7498`（具体 BDF 本机 `lspci` 自查，勿提交完整拓扑）

---

## 1. 关键结论（已核实）

### 1.1 软件栈必须是 **MPSS 4**，不是 MPSS 3

| 代际 | 型号举例 | 栈 | 主机驱动模块 |
|------|----------|-----|--------------|
| KNC | 3120/5110/**7120P** | **MPSS 3.8.x** | `mic`（x100） |
| **KNL PCIe** | **7220 / 7220P / 7240P** | **MPSS 4.4.x** | **`mic_x200` + `mic_x200_dma` + scif/vop/cosm…** |
| KNL 插座主机 | 7210/7230/7250 | **不需要 MPSS** | 当普通 CPU 装系统 |

公开说明（社区维护的 MPSS 补丁仓）：

- [jjkeijser/mpss](https://github.com/jjkeijser/mpss)：明确 **7220/7240 需要 MPSS 4**；7210 等主机型 **不需要** MPSS。  
- Wikipedia：KNL **PCIe 协处理器**（含 **7220P / 7240P / 7220A**）市场极短，约 2017 停推。

### 1.2 本机 Device ID 与 MPSS4 源码 **完全一致**

从 `jjkeijser/mpss` 的 `mpss4/mpss-modules`：

```c
// mic/mic_x200/mic_hw.h
#define INTEL_PCI_DEVICE_2260 0x2260
#define INTEL_PCI_DEVICE_2264 0x2264
// ...

// mic/mic_x200/mic_main.c — host 主功能绑定
{PCI_DEVICE(PCI_VENDOR_ID_INTEL, INTEL_PCI_DEVICE_2260)},
{PCI_DEVICE(...2262)}, {PCI_DEVICE(...2263)}, {PCI_DEVICE(...2265)},

// mic_x200_dma/mic_x200_dma.c — 副功能 2264
{PCI_DEVICE(PCI_VENDOR_ID_INTEL, 0x2264)},
```

加载顺序（`libmpssconfig`）：

```text
modprobe -a mic_x200_dma scif_bus vop_bus cosm_bus scif vop mic_cosm mic_x200
```

因此：本机 **不是「未知加速器」**，就是 MPSS4 的 **x200 协处理器**；之前无驱动是因为 **未装栈**，不是硬件认错。

### 1.3 在本机 Ubuntu 22.04 / kernel **6.8** 上 **无法** 直接编模块

2026-08-05 在本机对 `mpss4/mpss-modules` 执行 `make BUILD_CARD=false`（headers 已装）：

| 错误类型 | 示例 |
|----------|------|
| RHEL 宏 | `RHEL_RELEASE_CODE` / `RHEL_RELEASE_VERSION` 未定义（`-Werror=undef`） |
| 头文件 | `linux/dma_remapping.h` 不存在（旧 IOMMU API） |
| 支持上限 | 维护者注明：**未移植到新于 RHEL 8.3 (~4.18) 的内核**；Ubuntu 实测上限约 **4.15** 补丁线 |

**结论**: 主路径必须是 **旧发行版 + 旧内核**（推荐 Rocky/CentOS **8.x + 4.18** 或 RHEL7 系），**不是** 当前 6.8 工作系统硬编。

### 1.4 官方 tarball 现状

- 历史包名：`mpss-4.4.1`（Intel 最后 KNL 栈之一）。  
- 2026-08 探测：Intel 原下载链 **403 / 404**，需自备存档或从有权限的镜像/同事处获取。  
- 内核模块 + 用户态补丁源：`https://github.com/jjkeijser/mpss` 的 **`mpss4/`**（GPL，可改）。  
- 卡上镜像仍通常来自 **完整 MPSS 4.4.1 发行包**（`bzImage-knl-lb`、`initramfs-knl-lb.cpio.gz`、`persistent-FS-knl-lb` 等）。

## 2. 与 uni-framework（7120P）对照

| 步骤 | uni 7120P (KNC) | 本机 7220P (KNL) |
|------|-----------------|------------------|
| 安装栈 | MPSS **3.8.6** | MPSS **4.4.1** + 社区补丁 |
| 驱动 | `mic` | `mic_x200`, `mic_x200_dma`, … |
| 编译 | `icc -mmic` → `.mic` | 卡上跑 **标准 x86_64 + AVX-512**（或 Host 交叉到卡上 Linux） |
| 执行 | `micnativeloadex` | `micctrl` 起卡后 **ssh mic0** / SCIF；工具名类似但 **family=x200** |
| 卡上 OS | 老 BusyBox/mpss 根 | **KNL lb** 镜像（`bzImage-knl-lb` 等） |

方法论仍可抄：独立旧环境、检查脚本、Python 调度、PCIe 最小化。

## 3. 推荐 Bring-up 路径（冻结）

### 路径 A — **Rocky Linux 8.x 双系统 / 第二磁盘**（推荐）

1. 在空闲盘或分区装 **Rocky 8.9/8.10**（内核 **4.18**）。  
2. 准备 `mpss-4.4.1` 用户态包 + `jjkeijser/mpss` 的 **mpss4** 模块/补丁。  
3. 编译安装 `mpss-modules` → `modprobe` 上述模块。  
4. `micctrl --initdefaults`（或文档等价流程）→ 配置卡上 FS/镜像 → `service mpss start`。  
5. `micinfo` / `micctrl -s` → `online` → `ssh mic0`。  
6. 卡上跑 OpenMP AVX-512 hello；Host 侧再写 runner。

**AMD EPYC 风险**: 官方矩阵几乎只有 **Intel 主机**。可能卡在 IOMMU/DMA alias（本机 dmesg 已有 *fixed DMA alias*）。若 Rocky 上仍起不来，记录 dmesg 再决定是否换 Intel 主机做二次验证。

### 路径 B — 同机 **旧内核启动项**（次选）

- 理论：装 4.15/4.18 线内核 + 用户态。  
- 实际：Ubuntu 6.8 用户态与 MPSS4 用户态 C++/Boost 依赖冲突大；**不如双系统干净**。

### 路径 C — 在 6.8 上移植 mpss-modules（不推荐作主线）

- 工作量：IOMMU、内核 API、VFS、电源状态等整片改。  
- 仅当路径 A 硬件验证通过、且必须留在 Ubuntu 时再考虑。

## 4. Phase 1 验收标准

| ID | 标准 |
|----|------|
| P1-1 | `lspci -knn | grep 2260` 对应设备绑定 **`mic_x200`**（或等价） |
| P1-2 | DMA 功能 `8086:2264` 绑定 **`mic_x200_dma`** |
| P1-3 | `/sys/class/mic/mic0` 存在；`state` 可达 `online`/`booting` 可解释状态 |
| P1-4 | `micinfo` 报告 **x200 / 7220** 类 SKU、核数与内存 |
| P1-5 | 能向卡部署并执行 **hello**（ssh 或文档规定接口） |
| P1-6 | 10 分钟空载/轻载温度可接受；无持续 AER |

## 6. 获取软件的建议动作（人工）

1. 从合法来源获取：`mpss-4.4.1*.tar*`、`mpss-4.4.1*.rpm`（勿在文档中记录内部共享路径）。  
2. 克隆补丁仓（模块 GPL）：  
   `git clone https://github.com/jjkeijser/mpss.git`  
3. 卡上镜像文件（名称以发行包为准）：  
   `bzImage-knl-lb`, `System.map-knl-lb`, `initramfs-knl-lb.cpio.gz`, `efiImage-knl-lb.hddimg`, `persistent-FS-knl-lb*`  
4. 放到安全路径，例如 `third_party/mpss4/`（**勿提交大二进制到 git**，`.gitignore`）。
